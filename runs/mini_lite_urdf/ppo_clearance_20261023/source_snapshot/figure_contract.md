# 本次图表约定

- 问题：抬脚约束微调后的冻结策略，能否在原九场景全部通过，同时维持路径跟踪与机身平稳性？
- 证据：项目原验收入口的新 acceptance.json，以及全部 500 Hz trajectory.csv；必须核对策略指纹、原验收门槛、足端高度与误差统计。
- 作图：沿用已经确定的 Python / matplotlib 工作流和现有样式，复用等级为 exact reuse；只替换数据来源、标题和输出前缀。
- 面板：直线、曲线、转弯分层；每个面板包含 0、-5、+5 cm 初始偏移。三个面板提供不同路径条件下的验证边界。
- 映射：time_s 为横坐标 s；cross_track_m 乘 100 后为纵坐标 cm；path 与 y_offset_m 固定分类和排序。不平滑、不抽样、不删起步误差。
- 样本：固定场景各一次最终验收。候选筛选后冻结并复跑；这不是未见场景泛化测试，不绘制无依据置信区间。
- 输出：183 x 175 mm，中文字体至少 7 pt，PNG 600 dpi、SVG、PDF。用于 Obsidian，无投稿 TIFF 要求。
- 检查：500 Hz 全程 CSV 与报告逐项核对；多面板最终物理对齐、PDF 字号和碰撞审计，整图与面板目视检查。
- 原 PPO 奖励和损失曲线保留真实训练记录；局部权重搜索单独说明，不能把它记成新的 PPO 梯度训练。
